## TODO — Migration Gap Tracking

### 🔴 Gap 2 — Transaction Boundary Leak (CRITICAL)

**Status:** ☐ Not Verified

**Objective:**
Ensure all multi-step data mutations execute within a single transaction boundary, matching Python production atomicity.

**Required Rule:**

```
ALL related writes → ONE transaction
```

**Disallowed:**

```
Sequential writes without shared transaction
Cross-service writes outside same transaction context
```

**Verification Steps:**

* Search for transaction usage:

  ```
  grep -r "transaction(" backend/
  grep -r "withTransaction" backend/
  ```
* Inspect critical flows:

  * ☐ Certificate finalize
  * ☐ Ledger / credit_history insert
  * ☐ Customer balance updates
  * ☐ Item → total recalculations
* For each flow:

  * ☐ Are all DB calls inside the SAME transaction?
  * ☐ Is transaction context passed to all repo methods?

**Pass Condition:**
All related writes succeed or fail atomically within one transaction.

**Fail Condition:**
Any flow allows partial writes (some succeed, some fail).

**Risk if not fixed:**

* Financial inconsistency
* Orphan records
* Broken audit trails
* Failed reconciliation
