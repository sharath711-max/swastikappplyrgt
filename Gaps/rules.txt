## PROJECT RULES — KANBAN WORKFLOW (FINAL)

---

## 1. GENERAL SYSTEM RULES

1. System runs on multiple devices connected via local network (same IP).
2. Only ONE admin user account exists.
3. Admin can login from multiple devices simultaneously.
4. All actions must reflect in real-time across devices.
5. Workflow must be consistent across devices (no divergence).

---

## 2. WORKFLOW STATES

All modules (GT / ST / SC / GC / PC) follow:

Ongoing → Tested → Completed

Mapping:
- Ongoing = TODO
- Tested = IN_PROGRESS
- Completed = DONE

---

## 3. PHASE TRANSITION RULE

Each phase MUST enforce required fields before moving forward:

- Cannot move to Tested without purity data
- Cannot move to Completed without payment details
- No skipping phases
- No direct TODO → DONE

---

## 4. DEVICE ROLE ACTIONS

---

### DEVICE USER 1 — ENTRY CREATION

Location: Workflow Page → New Entry Modal

Allowed Actions:
- Save
- Cancel

Flow:
1. Click "New"
2. Enter sample details (GT/ST/SC/GC/PC)
3. Save

Result:
- Record created in **Ongoing** state
- Appears in Kanban board

---

### DEVICE USER 2 — TESTING PHASE

Location: Ongoing Card → Test Results Modal

Allowed Actions:
- Save Draft
- Submit
- Cancel

Flow:
1. Click Ongoing card
2. Enter purity values

Actions:

SAVE DRAFT:
- Saves entered purity
- Status remains **Ongoing**

SUBMIT:
- Validates purity fields
- Moves record to **Tested**

---

### DEVICE USER 1 — PAYMENT & FINALIZATION

Location: Tested Card → Payment & Status Modal

Allowed Actions:
- Save Draft
- Finalise
- Cancel

Editable:
- Amount
- Mode of payment

Read-only:
- All test data

Actions:

SAVE DRAFT:
- Saves payment details
- Status remains **Tested**

FINALISE:
- Validates required fields
- Calls: POST /api/workflow/finalize
- Moves record to **Completed**

---

## 5. COMPLETED STATE RULE

For ALL devices:

Location: Completed Card → Modal

Rules:
- All fields are READ-ONLY
- No edits allowed

Allowed Actions:
- Copy
- Print
- Close

---

## 6. PRINT RULE

- Print is allowed ONLY after Completed (DONE)
- Print must use snapshot (no live calculation)
- Item-level print allowed after DONE

---

## 7. REAL-TIME RULE

- All changes must sync across devices immediately
- No stale UI allowed
- Socket updates must use latest backend data
- No full board reload on each event

---

## 8. CONCURRENCY RULE

- System must handle multiple devices safely
- No overwrite of newer data
- OCC (version) must prevent stale updates
- Pending actions must not conflict with socket updates

---

## 9. FINALIZATION RULE (CRITICAL)

ALL finalization paths MUST use:

POST /api/workflow/finalize

❌ NOT ALLOWED:
- PATCH status → DONE directly
- POST /certificates/:id/results for finalize

---
