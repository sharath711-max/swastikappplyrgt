
## TODO — Migration Gap Tracking

### 🔴 Gap 5 — Snapshot / Derived Data Drift (CRITICAL)

**Status:** ☐ Not Verified

**Objective:**
Ensure all derived values (totals, tax, snapshot, hash) are always consistent with source data and computed atomically.

---

**Required Rule:**

```id="g5a"
items update → totals recalculated → snapshot generated → hash computed → SAME transaction
```

---

**Disallowed:**

```id="g5b"
Updating items without recalculating totals
Generating snapshot before totals update
Computing snapshot/hash outside transaction
Partial recomputation of derived data
```

---

**Verification Steps:**

Search for derived logic:

```id="g5c"
grep -r "total" backend/
grep -r "snapshot" backend/
grep -r "hash" backend/
```

Check critical flows:

* ☐ saveResults
* ☐ certificate finalize
* ☐ item add/update/remove
* ☐ snapshot/hash generation

For each:

* ☐ Are totals recalculated after item changes?
* ☐ Is snapshot generated after totals update?
* ☐ Is hash computed from final snapshot?
* ☐ Are ALL steps inside the SAME transaction?

---

**Pass Condition:**
Derived data (totals, snapshot, hash) always matches source data.

---

**Fail Condition:**
Any mismatch between items and totals/snapshot/hash is possible.

---

**Risk if not fixed:**

* Financial inconsistency
* Incorrect certificate values
* Broken audit integrity
* Snapshot/hash verification failure
